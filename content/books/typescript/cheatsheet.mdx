この章は、TypeScriptで型を指定する構文と記号を一覧で確認するためのチートシートです。`!` や `as const satisfies` のような記号は検索しにくいので、「この書き方は何をしているのか」「どれを使えばよいのか」をここで引けるようにしています。各構文の詳しい説明は、表の下にリンクした章にあります。

## 値に型を付ける構文

変数や式に型を付ける書き方です。**型チェックされるか**と、**変数の型が何になるか**が書き方ごとに違います。表の `T` には、次の `Endpoint` のような型が入ります。

```tsx
type Endpoint = { url: string; method: 'GET' | 'POST' };

const a: Endpoint = { url: '/api', method: 'GET' };              // 型注釈
const b = { url: '/api', method: 'GET' } satisfies Endpoint;     // satisfies
const c = { url: '/api', method: 'GET' } as const satisfies Endpoint;
```

| 書き方 | 型チェック | 変数の型 |
|---|---|---|
| `x: T` | される | `T` |
| `satisfies T` | される | 値から推論した型 |
| `as const satisfies T` | される | `readonly` のリテラル型 |
| `as const` | なし | `readonly` のリテラル型 |
| `as T` | 一部だけ | `T` |
| `as unknown as T` | なし | `T` |
| `x!` | なし | `null`・`undefined` を除いた型 |

- `b.method` の型は `'GET'`、`a.method` の型は `'GET' | 'POST'` です。どちらも値が `Endpoint` に合わなければコンパイルエラーになります
- `as T` は、型が大きく食い違うときだけエラーになります（TS2352）。プロパティが足りない値は通してしまいます

<Marker>迷ったら、書き換える変数は型注釈、定数は `satisfies`（必要なら `as const satisfies`）。`as` と `!` は、コンパイラには証明できないが値は正しいと確信できるときだけ使う。</Marker>

詳しくは[基本の型](/books/typescript/02-basic-types)（型注釈）と[型アサーションと型ガード](/books/typescript/08-assertion-and-guard)（`as`・`!`・`as const`・`satisfies`）で説明しています。

<Callout type="note">
### 「型チェックなし」の書き方は実行時に壊れうる

`as`・`as unknown as`・`!` は、コンパイラのチェックを止めて開発者の申告を採用します。申告が間違っていてもコンパイルは通り、実行時に `undefined` のプロパティを読んで `TypeError` になります。

</Callout>

## 型を絞り込む構文

`string | null` のようなユニオン型を、条件分岐で狭い型に絞る書き方です。

| 書き方 | 絞り込みの例 |
|---|---|
| `typeof x === 'string'` | `string \| number` → `string` |
| `x instanceof Date` | `Date \| string` → `Date` |
| `'kind' in x` | `Cat \| Dog` → `Cat` |
| `x.type === 'ok'` | `Ok \| Err` → `Ok` |
| `x != null` | `string \| null` → `string` |
| `x is T` | 関数が `true` を返した分岐で `T` |
| `asserts x is T` | 関数を呼んだ後ろで `T` |

`x is T` と `asserts x is T` は関数の戻り値の型に書きます。

```tsx
function isUser(x: unknown): x is User { /* ... */ }
function assertString(x: unknown): asserts x is string { /* ... */ }
```

この2つは、判定ロジックが正しいかをTypeScriptが確かめません。`x is User` と書いた関数が間違った判定をしても、コンパイルは通ります。

詳しくは[型の絞り込み](/books/typescript/05-narrowing)（`typeof`・`in`・`asserts` など）と[型アサーションと型ガード](/books/typescript/08-assertion-and-guard)（`is`）で説明しています。

## 型の位置で使う記号

`type X = ...` の右辺や、`: ` の後ろなど、型を書く場所で使う記号です。

| 書き方 | 意味 | 例 |
|---|---|---|
| `A \| B` | ユニオン型（AまたはB） | `string \| null` |
| `A & B` | 交差型（両方のプロパティを持つ） | `User & Admin` |
| `'GET'` | リテラル型（その値だけ） | `'GET' \| 'POST'` |
| `p?: T` | 省略できるプロパティ | `name?: string` |
| `readonly p: T` | 再代入できないプロパティ | `readonly id: number` |
| `keyof T` | キーのユニオン型 | `keyof User` |
| `typeof x` | 変数の型を取り出す | `typeof config` |
| `T[K]` | プロパティの型 | `User['name']` |
| `T[number]` | 配列の要素の型 | `Items[number]` |
| `<T extends U>` | 型引数の制約 | `<K extends keyof T>` |
| `A extends B ? X : Y` | 条件型 | `T extends string ? 1 : 0` |
| `` `id-${number}` `` | テンプレートリテラル型 | `'id-1'` を許す |

詳しくは次の章で説明しています。

- `|`・リテラル型: [ユニオン型とリテラル型](/books/typescript/04-union-and-literal)
- `&`: [型エイリアスとインターフェース](/books/typescript/03-type-alias-and-interface)
- `?:`・`readonly`: [基本の型](/books/typescript/02-basic-types)
- `keyof`・`extends`: [ジェネリクス](/books/typescript/07-generics)
- `typeof`・`T[K]`・条件型・テンプレートリテラル型: [実践パターン集](/books/typescript/14-practical-patterns)

<SpeechBubble character="/images/oksign_man_color.png" name="先生">
`typeof` は書く場所で意味が変わります。`if (typeof x === 'string')` のように値の位置に書けばJavaScriptの演算子で、文字列を返します。`type C = typeof config` のように型の位置に書けば、TypeScriptが変数の型を取り出します。

## 似ていて混同しやすい組み合わせ

- **`x!.name` と `x?.name`**  
  `!` は型から `null` を消すだけで、実行時に `x` が `null` なら `TypeError` になります。`?.` は実行時に `x` が `null` なら `undefined` を返します。→ [型アサーションと型ガード](/books/typescript/08-assertion-and-guard)
- **`a ?? b` と `a || b`**  
  `??` は `a` が `null`・`undefined` のときだけ `b` を返します。`||` は `0`・`''`・`false` のときも `b` を返します。→ [演算子と式（JavaScript本）](/books/javascript/03-operators-and-expressions)
- **`x?: T` と `x: T | undefined`**  
  `x?:` はプロパティ自体を省略できます。`T | undefined` は値に `undefined` を入れられますが、プロパティは書く必要があります。→ [関数と型](/books/typescript/06-functions)
- **`as const` と `as T`**  
  `as const` は型を狭くする方向にだけ働くので安全です。`as T` は型チェックを止めます。→ [型アサーションと型ガード](/books/typescript/08-assertion-and-guard)
- **`satisfies T` と `: T`**  
  どちらも型チェックされます。変数の型は、`satisfies` なら推論結果、`: T` なら `T` です。→ [型アサーションと型ガード](/books/typescript/08-assertion-and-guard)
- **`any` と `unknown`**  
  `any` は型チェックを止めます。`unknown` は絞り込むまでプロパティを読めません。→ [基本の型](/books/typescript/02-basic-types)

## ちゃんと使うためのポイント

- 値に型を付ける構文は、「型チェックされるか」と「変数の型が何になるか」の2点で選ぶ
- <Marker>`as`・`as unknown as`・`!` は型チェックを止める。使う前に、型注釈・`satisfies`・型ガードで書けないかを確認する</Marker>
- `is` と `asserts` は判定ロジックの正しさを保証しない。判定の中身は自分で確かめる
- `typeof` は値の位置と型の位置で意味が違う

エラーメッセージから原因を探したいときは、[TypeScriptのエラーコード別リファレンス](/books/typescript/common-errors)を参照してください。
