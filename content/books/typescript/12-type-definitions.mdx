## .d.tsファイルとは

`.d.ts` ファイルは**型情報だけを記述したファイル**です。実行時のJavaScriptコードは含まず、TypeScriptコンパイラが型チェックに使います。

```typescript
// example.d.ts
export declare function formatDate(date: Date, format: string): string;
export declare const VERSION: string;
```

`declare` キーワードは「この関数/変数は別の場所で実装されている」ことを表します。`.d.ts` は実装ではなく**契約書**のようなものです。

## @typesパッケージ — DefinitelyTyped

JavaScriptで書かれたライブラリに型定義がない場合、コミュニティがDefinitelyTypedリポジトリで型定義を管理しています。

```bash
npm install --save-dev @types/react @types/node @types/express
```

TypeScriptは `node_modules/@types/` 配下を自動的に参照するため、インストールするだけで型が効きます。

### 型定義が同梱されているライブラリ

すべてのライブラリに `@types` が必要なわけではありません。ライブラリ本体に `.d.ts` が含まれている場合は不要です。

```bash
# @types 不要 — ライブラリ本体に型定義が含まれている
npm install zod        # TypeScriptで書かれている
npm install axios      # .d.ts が同梱されている
npm install date-fns   # TypeScriptで書かれている
```

見分け方は、ライブラリの `package.json` に `"types"` または `"typings"` フィールドがあるかどうかです。

```json
// axiosの package.json（抜粋）
{
  "types": "./index.d.ts"
}
```

<Callout type="info">
### @types が必要かどうかの判断

`npm install some-lib` の後にエディタで `import` してみて、型エラーが出なければ不要。「Could not find a declaration file for module」と出たら `@types/some-lib` をインストールする。
</Callout>

## 型定義がないライブラリへの対処

`@types` パッケージも存在しないライブラリの場合、`declare module` で最低限の型定義を書きます。

```typescript
// src/types/some-legacy-lib.d.ts
declare module 'some-legacy-lib' {
  export function doSomething(input: string): void;
  export default class Client {
    constructor(apiKey: string);
    fetch(url: string): Promise<unknown>;
  }
}
```

すべてのAPIを詳細に型付けする必要はありません。自分が使う部分だけ定義すれば十分です。

最小限の型定義で `any` を使う場合：

```typescript
// src/types/some-legacy-lib.d.ts
declare module 'some-legacy-lib' {
  const content: any;
  export default content;
}
```

## グローバル型定義

プロジェクト全体で使う型を `global.d.ts` に定義できます。

```typescript
// src/types/global.d.ts

// 環境変数の型定義
declare namespace NodeJS {
  interface ProcessEnv {
    DATABASE_URL: string;
    NEXT_PUBLIC_API_URL: string;
    NODE_ENV: 'development' | 'production' | 'test';
  }
}

// Window オブジェクトの拡張
interface Window {
  gtag: (...args: unknown[]) => void;
}
```

<Figure src="/images/deskwork_check_woman_color.png" alt="型定義の管理" caption="型定義ファイルはsrc/types/に集めておくとプロジェクトの見通しがよくなる" maxWidth="240px" />

環境変数の型を定義しておくと、`process.env.DATABASE_URL` が `string` として推論され、`undefined` チェックが不要になります。

## 型定義ファイルの配置

型定義ファイルは `tsconfig.json` の `include` に含まれるパスに置きます。

```text
src/
  types/
    global.d.ts        ← グローバル型定義
    some-legacy-lib.d.ts ← ライブラリの型定義
    api-response.ts    ← アプリの型定義（通常の .ts）
```

<Callout type="warning">
### .d.ts と .ts の使い分け

`.d.ts` は「型だけ」を記述するファイル。自分のアプリケーションの型定義（APIレスポンスの型など）は通常の `.ts` ファイルに書く。`.d.ts` はJSライブラリへの型付けやグローバル型の拡張に使う。
</Callout>

## ちゃんと使うためのポイント

- <Marker>`.d.ts` は型情報だけのファイル。実装は含まない</Marker>
- `@types/xxx` はコミュニティ管理の型定義。ライブラリ本体に型があれば不要
- 型定義がないライブラリは `declare module` で最低限の型を書く
- 環境変数や `Window` の拡張はグローバル型定義で対応する
- 自アプリの型定義は `.ts`、外部ライブラリの型付けは `.d.ts` で書く
