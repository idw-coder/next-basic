MUIで文字を書くとき、素の `<p>` や `<h2>` を置いてもかまいません。ただし `Typography` を使うと、テーマで決めたフォントサイズや行間が自動で当たります。

このコンポーネントには、他のUIライブラリにあまりない考え方が入っています。<Marker>「どう見えるか」と「HTMLとして何であるか」を別々のpropで指定する</Marker>という設計です。

<SpeechBubble character="/images/usingcomputer_suit_woman_color.png" name="学習者">
`variant="h4"` って書いたら `<h4>` タグになるんじゃないの？わざわざ2つに分ける意味がわからない…。
</SpeechBubble>

既定ではそのとおり `<h4>` になります。分けられるのは、**見た目の大きさと見出しレベルが一致しない場面があるから**です。

---

## variantとcomponentの役割

```tsx
<Typography variant="h4" component="h2">
  セクション見出し
</Typography>
```

| prop | 役割 |
| --- | --- |
| `variant` | 見た目のプリセット（フォントサイズ・太さ・行間） |
| `component` | 実際に描画されるHTMLタグ |

上の例は「文字の大きさは `h4` 相当、HTMLとしては `<h2>`」という指定です。

なぜこれが要るのか。ページ内の2つ目の大見出しは、HTMLの構造上は `<h2>` であるべきですが、デザイン上は小さめにしたいことがあります。`<h4>` タグで書いてしまうと、見出しレベルが `h1` → `h4` と飛び、スクリーンリーダーでの拾い読みがしづらくなります。

<Marker>見た目のためにタグを選ばない</Marker>。これがこのpropが存在する理由です。

## variantごとに描画されるタグ

`component` を省略したときに何になるかは、決まった対応表があります。

| variant | 描画されるタグ |
| --- | --- |
| `h1` 〜 `h6` | 同じ名前のタグ（`<h1>` 〜 `<h6>`） |
| `subtitle1` / `subtitle2` | **`<h6>`** |
| `body1` / `body2` | `<p>` |
| `button` / `caption` / `overline` | `<span>` |

<Callout type="warning" title="subtitleは見出しになる">
`subtitle1` と `subtitle2` は、名前から受ける印象と違って **`<h6>` で描画されます**。「本文の補足」のつもりでページ内に何個も置くと、HTMLの見出しが大量に生まれます。

補足テキストとして使いたいなら、`component` で打ち消してください。

```tsx
<Typography variant="subtitle2" component="p">
  補足のテキスト
</Typography>
```
</Callout>

### どのタグになるかの決定順

実装では、次の順で最初に見つかったものが使われます。

1. `component` prop（指定があれば最優先）
2. `variantMapping` prop（そのコンポーネントだけの対応表）
3. 既定の対応表（上の表）
4. どれにも当てはまらなければ `<span>`

`button` / `caption` / `overline` が `<span>` になるのは、既定の対応表に載っておらず4番目に落ちるためです。

## 余白は自分で付ける

`Typography` の既定スタイルには **`margin: 0`** が入っています。ブラウザが `<h1>` や `<p>` に付ける余白は消えます。

```tsx
<Typography variant="h4">見出し</Typography>
<Typography variant="body1">本文がすぐ下に詰まる</Typography>
```

意図的な設計です。余白はレイアウト側で決めるという考え方で、`Stack` の `spacing` や `sx` の `mb` で付けます。

手軽に下余白だけ足したい場合は `gutterBottom` が使えます。

```tsx
<Typography variant="h4" gutterBottom>見出し</Typography>
```

これで `margin-bottom: 0.35em` が付きます。**文字サイズに比例する相対値**なので、見出しが大きいほど余白も広がります。厳密に揃えたいときは `sx={{ mb: 2 }}` のほうが確実です。

## noWrap — はみ出しを省略記号にする

テーブルのセルやカードのタイトルで、長い文字列が折り返して高さを壊すことがあります。

```tsx
<Typography noWrap>とても長いタイトルがここに入ります</Typography>
```

これ1つで、次の3つのCSSがまとめて当たります。

| プロパティ | 値 |
| --- | --- |
| `overflow` | `hidden` |
| `text-overflow` | `ellipsis` |
| `white-space` | `nowrap` |

結果として、はみ出した部分が `…` で省略されます。

### 2行・3行で省略したいとき

`noWrap` は `white-space: nowrap` を含むので、**1行での省略専用**です。カードの説明文を2行で止めたい、という用途には使えません。複数行での省略には専用のpropがなく、`sx` にCSSの `-webkit-line-clamp` を書きます。

```tsx
<Typography
  variant="body2"
  sx={{
    display: '-webkit-box',
    WebkitBoxOrient: 'vertical',
    WebkitLineClamp: 2,
    overflow: 'hidden',
  }}
>
  カードの説明文など、長くなる可能性があるテキスト。2行を超えた分は省略記号になります。
</Typography>
```

4つのプロパティはセットで必要です。`WebkitLineClamp` の数値が、表示する行数です。

<Callout type="info" title="効かないときは幅を見る">
`noWrap` は「決まった幅からはみ出した分」を省略する仕組みです。親要素に幅の制限がないと、そもそもはみ出さないので何も起きません。Flexboxの中では `min-width: 0` が必要になることもあります。
</Callout>

<SpeechBubble character="/images/oksign_man_color.png" name="先生" side="right">
`noWrap` が効かない相談のほとんどは、MUIではなくCSSの話です。省略記号は「幅が決まっていること」が前提だと覚えておいてください。
</SpeechBubble>

## colorとalign

色はテーマのパスを文字列で渡せます。

```tsx
<Typography color="text.secondary">補足のテキスト</Typography>
<Typography color="error">エラーメッセージ</Typography>
```

`text.primary` / `text.secondary` のようなパスのほか、`primary` や `error` といった役割の名前も受け取ります。<Marker>生の色コードを書かずテーマ経由にしておくと、ダークモードで自動的に切り替わります</Marker>。

揃え方は `align` です。

```tsx
<Typography align="center">中央寄せ</Typography>
```

`'inherit'`（既定）/ `'left'` / `'center'` / `'right'` / `'justify'` から選びます。

## 画面幅で文字サイズを変える

スマートフォンでは見出しを小さく、PCでは大きくしたい場面です。方法は3つあり、変えたい範囲で選びます。

| 方法 | 変わる範囲 |
| --- | --- |
| `sx` の `fontSize` にブレークポイントを書く | その1か所の文字サイズだけ |
| `sx` の `typography` にブレークポイントを書く | その1か所のvariantごと（サイズ・太さ・行間） |
| テーマを `responsiveFontSizes()` で包む | アプリ全体の見出し |

```tsx
// 文字サイズだけ変える
<Typography variant="h4" component="h1" sx={{ fontSize: { xs: '1.5rem', md: '2.125rem' } }}>
  ページタイトル
</Typography>

// variantごと切り替える（狭い画面はh5、md以上はh3の見た目）
<Typography component="h1" sx={{ typography: { xs: 'h5', md: 'h3' } }}>
  ページタイトル
</Typography>
```

2つ目の書き方では `variant` propを使わず、`sx` の `typography` キーにvariantの名前を渡します。`variant` propは既定の `body1` のままなので、`component` を書かないと `<p>` で描画されます。見出しにするなら `component` でHTMLタグを指定します。

アプリ全体で一括して対応するなら、テーマを `responsiveFontSizes()` に通します。

```tsx
import { createTheme, responsiveFontSizes } from '@mui/material/styles';

const theme = responsiveFontSizes(createTheme());
```

既定のテーマに適用すると、`h3` は次のように変わります。

| | `h3` の `font-size` |
| --- | --- |
| 適用前 | 常に `3rem` |
| 適用後 | `2rem` → 600px以上で `2.5707rem` → 900px以上で `2.7849rem` → 1200px以上で `3rem` |

<Marker>大きい画面でのサイズは元のまま、狭い画面で小さくなる方向に調整されます</Marker>。`body1` などの本文は変わりません（適用後も `1rem` のまま）。

<SpeechBubble character="/images/oksign_man_color.png" name="先生" side="right">
ページごとに `fontSize` を書いて回るより、先に `responsiveFontSizes()` を入れて、それでも合わない箇所だけ `sx` で調整するほうが、書く量も揃い方も良くなるよ。
</SpeechBubble>

## リンクやNext.jsのLinkとして描画する

`component` にはHTMLタグの名前だけでなく、コンポーネントも渡せます。渡したコンポーネントのpropsは、そのまま `Typography` に書けます。

```tsx
import Link from 'next/link';

<Typography component={Link} href="/about" variant="body2" color="primary">
  このサイトについて
</Typography>
```

`href` は `Link` のpropですが、`Typography` に書いて型エラーになりません。見た目は `body2`、動作はNext.jsのクライアント側遷移になります。

## プロジェクト全体で対応表を変える

「このアプリでは `subtitle1` を常に `<p>` にしたい」という方針があるなら、テーマにまとめられます。

```tsx
createTheme({
  components: {
    MuiTypography: {
      defaultProps: {
        variantMapping: {
          subtitle1: 'p',
          subtitle2: 'p',
        },
      },
    },
  },
});
```

毎回 `component="p"` と書く必要がなくなります。カスタマイズの段階としては、[カスタマイズの4段階](/books/mui/customization-levels)で扱った「全体の方針はテーマに書く」に当たります。

## v9で削除されたprop

古い記事には次の書き方が出てきます。

```tsx
// v8以前。v9では動かない
<Typography paragraph>段落テキスト</Typography>
```

`paragraph` は `<p>` で描画しつつ下余白を付けるpropでしたが、**v9の型定義には存在しません**。`body1` が既定で `<p>` になるため、役割が重複していたものと考えられます。

現在はこう書きます。

```tsx
<Typography variant="body1" gutterBottom>段落テキスト</Typography>
```

また、[sx propの章](/books/mui/sx-prop)で扱ったとおり、`Typography` からは **system propsも削除**されています。`<Typography mt={2}>` は動かないので、`sx` に移してください。

## よくあるハマりどころ

### 見出しの下に余白がない

`margin: 0` が既定です。`gutterBottom` か `sx` で付けます。

### `subtitle` を並べたら見出し構造が壊れた

`subtitle1` / `subtitle2` は `<h6>` で描画されます。補足なら `component="p"` を指定します。

### `noWrap` が効かない

親要素の幅が決まっていません。Flexboxの子なら `sx={{ minWidth: 0 }}` も併せて確認します。

### `<Typography mt={2}>` が無視される

v9でsystem propsが削除されました。`sx={{ mt: 2 }}` に書き換えます。

### 文字サイズをテーマで変えたのに一部だけ変わらない

`variant` を指定していない `Typography` は `body1` 相当になります。変更したのが `h1` の設定だけなら、本文には反映されません。

---

## ちゃんと使うためのポイント

- <Marker>`variant` は見た目、`component` はHTMLタグ。見た目のためにタグを選ばない</Marker>
- `subtitle1` / `subtitle2` は既定で `<h6>`。補足に使うなら `component="p"`
- `button` / `caption` / `overline` は `<span>`
- 既定は `margin: 0`。余白は `gutterBottom` か `sx` で付ける
- `noWrap` は幅が決まっていて初めて効く
- 色はテーマのパスで指定するとダークモードに追従する
- v9では `paragraph` prop とsystem propsが削除された
- `noWrap` は1行専用。複数行の省略は `sx` に `WebkitLineClamp` を書く
- 画面幅で文字サイズを変えるなら、まずテーマを `responsiveFontSizes()` に通す

色やフォントをまとめて管理する方法は、[テーマの章](/books/mui/theme-and-tokens)で扱っています。
