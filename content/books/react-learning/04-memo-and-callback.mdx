この章で扱う `useRef`・`useMemo`・`useCallback` は、いずれも **再レンダーを引き起こさない** フックです。

## 前提 — 再レンダーのたびに何が起きるか

Reactではstateが変わるとコンポーネント関数が再実行されます。
関数が再実行されるということは、関数内のすべてのコードがもう一度走るということです。

```tsx
function UserList({ users }: { users: User[] }) {
  // 再レンダーのたびに、この並べ替え処理が毎回走る
  const sorted = users.slice().sort((a, b) => a.name.localeCompare(b.name));

  // 再レンダーのたびに、この関数オブジェクトが毎回新しく作られる
  const handleClick = (id: string) => {
    console.log(id);
  };

  // 再レンダーのたびに、この変数は0にリセットされる
  let renderCount = 0;
  renderCount++; // 常に1

  return (
    <ul>
      {sorted.map((u) => (
        <li key={u.id} onClick={() => handleClick(u.id)}>
          {u.name}
        </li>
      ))}
    </ul>
  );
}
```

ローカル変数は毎回消えて作り直される。計算も毎回やり直される。関数オブジェクトも毎回新しく生まれる。
この3つの問題に対して、それぞれ `useRef`・`useMemo`・`useCallback` が解決策を提供します。

## useRef — 再レンダーせずに値を保持する

`useRef` は、再レンダーをまたいで値を保持するが、値を変えても再レンダーを引き起こさないフックです。

`useState` との違いを比較するとわかりやすいです。

```tsx
const [count, setCount] = useState(0);
// setCount(1) → stateが変わる → 再レンダーが走る → UIが更新される

const countRef = useRef(0);
// countRef.current = 1 → 値は変わる → 再レンダーは走らない → UIはそのまま
```

`useRef` は `.current` プロパティを持つオブジェクトを返します。
`.current` を直接書き換えられますが、Reactはその変更を監視していないので再レンダーは起きません。

### いつuseStateではなくuseRefを使うのか

判断基準は「その値がUIの表示に影響するかどうか」です。

画面に表示する値なら `useState` を使います。値が変わったときに画面を更新してほしいからです。
画面には表示しないが裏側で覚えておきたい値なら `useRef` を使います。再レンダーのコストが不要だからです。

### 典型的な使い方

**DOM要素への参照**

最もよく使うパターンです。JSXの `ref` 属性に渡すと、Reactがマウント時にそのDOM要素を `.current` に入れてくれます。

```tsx
function TextInput() {
  const inputRef = useRef<HTMLInputElement>(null);

  const handleClick = () => {
    // DOM要素に直接アクセスできる
    inputRef.current?.focus();
  };

  return (
    <>
      <input ref={inputRef} />
      <button onClick={handleClick}>フォーカスする</button>
    </>
  );
}
```

**前回の値を覚えておく**

```tsx
function Counter() {
  const [count, setCount] = useState(0);
  const prevCountRef = useRef(0);

  useEffect(() => {
    prevCountRef.current = count; // レンダー後に前回の値を保存
  });

  return (
    <p>
      現在 {count}（前回 {prevCountRef.current}）
    </p>
  );
}
```

**タイマーIDの保持**

03章のuseEffectで見たタイマーのIDも、コンポーネントの外から参照したい場合は `useRef` で保持します。

```tsx
function StopWatch() {
  const [seconds, setSeconds] = useState(0);
  const intervalRef = useRef<number | null>(null);

  const start = () => {
    intervalRef.current = window.setInterval(() => {
      setSeconds((s) => s + 1);
    }, 1000);
  };

  const stop = () => {
    if (intervalRef.current !== null) {
      window.clearInterval(intervalRef.current);
    }
  };

  return (
    <div>
      <p>{seconds}秒</p>
      <button onClick={start}>開始</button>
      <button onClick={stop}>停止</button>
    </div>
  );
}
```

タイマーIDは画面に表示しないので `useState` ではなく `useRef` が適切です。
もし `useState` で持つと、IDが変わるたびに不要な再レンダーが発生します。

## useMemo — 計算結果のメモ化

`useMemo` は、依存配列の値が変わらない限り前回の計算結果を使い回すフックです。

```tsx
import { useMemo } from 'react';

function UserList({ users }: { users: User[] }) {
  const sorted = useMemo(
    () => users.slice().sort((a, b) => a.name.localeCompare(b.name)),
    [users], // usersが変わったときだけ再計算する
  );

  return (
    <ul>
      {sorted.map((u) => (
        <li key={u.id}>{u.name}</li>
      ))}
    </ul>
  );
}
```

`useMemo` に渡すのは「値を返す関数」と「依存配列」です。
依存配列の中身が前回と同じなら関数は実行されず、キャッシュされた前回の戻り値がそのまま返ります。

### useEffectとの違い

`useMemo` と `useEffect` はどちらも依存配列を持ち、「値が変わったら何かする」という判定の仕組みは同じです。
しかし「何をするか」と「いつやるか」がまったく異なります。

`useMemo` はレンダー中に同期的に値を計算して返します。
コンポーネント関数の実行中に「この値が今すぐ必要だから計算する。ただし依存が前回と同じならキャッシュを返す」という動きです。

`useEffect` はレンダーが終わってDOMに反映されたあとに実行されます。
値を返すためのものではなく、外部との同期（API呼び出し、タイマー設定など）のためのものです。

```tsx
function Example({ userId }: { userId: string }) {
  // useMemo — レンダー中に計算される。結果はすぐ使える。
  const displayName = useMemo(() => {
    return computeExpensiveName(userId);
  }, [userId]);

  // useEffect — レンダー後に走る。結果が届くのは次の再レンダー以降。
  useEffect(() => {
    fetchUserProfile(userId).then(setProfile);
  }, [userId]);

  return <p>{displayName}</p>;
}
```

判断基準はシンプルで、レンダー中に値が欲しいなら `useMemo`、レンダー後に外部と何かやりとりしたいなら `useEffect` です。

### useRefとの違い

`useRef` も `useMemo` も再レンダーを起こさずに値を保持しますが、用途が違います。

`useRef` は値をそのまま保持し続けます。自分で `.current` を書き換えるまで変わりません。
`useMemo` は依存配列が変わったら自動的に再計算します。「派生データ」（元のデータから計算で得られるデータ）のキャッシュに向いています。

```tsx
// useRef — 自分で書き換えるまでずっと同じ値
const timerIdRef = useRef<number | null>(null);

// useMemo — usersが変わったら自動的にソートし直す
const sorted = useMemo(() => sortUsers(users), [users]);
```

## useCallback — 関数のメモ化

`useCallback` は、依存配列の値が変わらない限り同じ関数オブジェクトを使い回すフックです。

```tsx
import { useCallback } from 'react';

function Parent() {
  const [count, setCount] = useState(0);

  const handleClick = useCallback(() => {
    console.log('clicked');
  }, []); // 依存する値がないので、常に同じ関数オブジェクトが返る

  return <Child onClick={handleClick} />;
}
```

実は `useCallback` は `useMemo` の特殊ケースです。
関数を返す `useMemo` と全く同じ動きをします。

```tsx
// この2つは同じ意味
const handleClick = useCallback(() => {
  /* ... */
}, [deps]);
const handleClick = useMemo(
  () => () => {
    /* ... */
  },
  [deps],
);
```

`useCallback` は「関数をメモ化する」という意図が読み取りやすいので、関数をメモ化したいときはこちらを使います。

## useCallbackが意味を持つ場面

`useCallback` 単体では、ほとんどの場合パフォーマンスに影響しません。
関数オブジェクトの生成コスト自体はごく小さいからです。

`useCallback` が意味を持つのは、渡した先で参照の同一性が重要になる場合です。

### React.memoと組み合わせる

`React.memo` でラップされた子コンポーネントは、propsが前回と同じなら再レンダーをスキップします。
しかし、親が再レンダーされるたびに新しい関数オブジェクトがpropsとして渡されると、
子は「propsが変わった」と判断して毎回再レンダーされてしまいます。

```tsx
// React.memoでラップ → propsが同じなら再レンダーをスキップ
const ExpensiveChild = React.memo(function ExpensiveChild({ onClick }: { onClick: () => void }) {
  // 重い描画処理...
  return <button onClick={onClick}>実行</button>;
});

function Parent() {
  const [count, setCount] = useState(0);

  // useCallbackなし → 毎回新しい関数 → ExpensiveChildも毎回再レンダー
  // useCallbackあり → 同じ関数 → ExpensiveChildの再レンダーをスキップ
  const handleClick = useCallback(() => {
    console.log('clicked');
  }, []);

  return (
    <div>
      <p>{count}</p>
      <button onClick={() => setCount((c) => c + 1)}>+1</button>
      <ExpensiveChild onClick={handleClick} />
    </div>
  );
}
```

### useEffectの依存配列に関数を含める場合

`useEffect` の依存配列に関数を入れるとき、その関数が毎回新しく生成されるとエフェクトが毎回再実行されます。
`useCallback` で関数の参照を安定させることで、意図しないエフェクトの再実行を防げます。

## 使うべきか迷ったときの判断基準

`useMemo` と `useCallback` はあくまで最適化の手段であり、正しさのためのものではありません。
これらがなくてもアプリは正しく動きます。

**使う場面**

- 計算が明らかに重い（大量データのソート、フィルタリング、集計など）
- `React.memo` された子コンポーネントにpropsとして渡す値や関数
- `useEffect` の依存配列に含まれるオブジェクトや関数の参照を安定させたい

**使わなくてよい場面**

- 単純な計算（四則演算、文字列結合、短い配列の操作など）
- `React.memo` されていない子コンポーネントへのprops（メモ化しても子は結局再レンダーされる）
- コンポーネント内で完結する関数（子に渡さない、依存配列にも入れない）

迷ったら「まずメモ化なしで書く → 実際に遅いと感じたら計測してボトルネックを特定 → 必要な箇所にだけ入れる」の順序で進めてください。
最初からすべてをメモ化するのは、コードの複雑さが増す割に効果が薄いことがほとんどです。

## まとめ

`useRef` は再レンダーなしに値を保持する手段で、DOM参照やタイマーIDなどUIに直接表示しないデータに使います。
`useMemo` は計算結果を、`useCallback` は関数オブジェクトをメモ化し、依存配列が変わらない限り前回の値を使い回します。

3つに共通するのは「再レンダーを引き起こさない」という性質です。
`useState` が「変更 → 再レンダー → UI更新」のサイクルを回すフックなのに対し、
この章のフックはそのサイクルの外側で値を管理するためのものです。
