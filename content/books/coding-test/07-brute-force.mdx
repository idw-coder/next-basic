Part 3は解法パターン編です。初回は**全探索（brute force）**——「候補を全部試す」という、最も素朴で最も重要な解法から始めます。

<SpeechBubble character="/images/question_woman_04_color.png" name="学習者">
全部試すって、それ「アルゴリズム」なの…？工夫がないというか、力任せというか。
</SpeechBubble>

それがれっきとしたアルゴリズムなんです。理由は2つあります。第一に、**制約が小さければ全探索が正解**です。第2章の表を思い出してください——N ≤ 20なら2^N通り試してよいと、出題者が制約で言っています。第二に、貪欲法もDPも「全探索の無駄を削ったもの」です。**まず全探索で解ける形にしてから削る**のが、応用解法への正しい登り方です。

## 型1: 多重ループの全探索

> **問題**: N個の商品から3つ選んで、合計がちょうどX円になる組み合わせはあるか。（N ≤ 100）

100個から3つ選ぶ組み合わせは約16万通り。10^8に遠く及ばないので全部試します。

```typescript
function hasTriple(prices: number[], x: number): boolean {
  const n = prices.length;
  for (let i = 0; i < n; i++) {
    for (let j = i + 1; j < n; j++) {       // j は i+1 から（重複選択を防ぐ）
      for (let k = j + 1; k < n; k++) {
        if (prices[i] + prices[j] + prices[k] === x) return true;
      }
    }
  }
  return false;
}
```

「組み合わせ（順序なし）」は `j = i + 1` から始めて重複を避ける——この添字の切り方は頻出イディオムです。3重ループはO(N³)なので、N ≤ 500くらいまでが目安です。

## 型2: 順列の全列挙

「並べ方を全部試したい」ときは順列の列挙です。N ≤ 10なら10! ≈ 363万通りで間に合います。

> **問題**: N個の都市をすべて1回ずつ巡るとき、移動距離の合計の最小値を求めよ。（N ≤ 8、巡回セールスマン問題の小規模版）

```typescript
function permutations<T>(arr: T[]): T[][] {
  if (arr.length <= 1) return [arr];
  const result: T[][] = [];
  for (let i = 0; i < arr.length; i++) {
    const rest = [...arr.slice(0, i), ...arr.slice(i + 1)];
    for (const p of permutations(rest)) {
      result.push([arr[i], ...p]);        // 先頭を固定して残りの順列を再帰生成
    }
  }
  return result;
}

// 全順列について距離を計算し、最小を取る
let best = Infinity;
for (const route of permutations(cities)) {
  best = Math.min(best, totalDistance(route));
}
```

順列生成は再帰の練習台としても優秀です。「先頭を1つ選ぶ→残りで同じ問題を解く」という再帰の分解は、後のDFS・バックトラッキングにそのままつながります。

## 型3: bit全探索 — この章の主役

**「N個のものそれぞれについて、選ぶ/選ばない」の2^N通りを試す**方法です。AtCoder ABCのC問題で繰り返し出てくる型で、節の最後に実際の過去問を挙げています。

> **問題**: N個の数から好きな個数選んで、合計をちょうどXにできるか。（N ≤ 20）

N ≤ 20 は「2^20 ≈ 100万通り、試してよし」の合図です（[計算量の章](/books/coding-test/02-big-o)の表）。

### 整数を「選び方」とみなす

鍵になるのは、**整数のビット列を「選び方」とみなす**発想です。`nums = [3, 5, 7]`（N = 3）で、0〜7の8個の整数がどの選び方になるかを全部並べます。

| 整数 | 2進数 | 選ぶもの | 合計 |
|---|---|---|---|
| 0 | `000` | なし | 0 |
| 1 | `001` | 0番目（3） | 3 |
| 2 | `010` | 1番目（5） | 5 |
| 3 | `011` | 0番目と1番目（3, 5） | 8 |
| 4 | `100` | 2番目（7） | 7 |
| 5 | `101` | 0番目と2番目（3, 7） | 10 |
| 6 | `110` | 1番目と2番目（5, 7） | 12 |
| 7 | `111` | 全部（3, 5, 7） | 15 |

8行で「選ぶ/選ばない」の組み合わせがちょうど1回ずつ出てきます。0から2^N − 1まで数えるだけで、選び方を漏れなく重複なく列挙できるわけです。

<SpeechBubble character="/images/question_woman_04_color.png" name="学習者">
待って、`001` が「0番目だけ選ぶ」なの？左から読むと、0番目は左端の `0` じゃない？
</SpeechBubble>

ここが最初のつまずきどころです。<Marker>2進数の桁は右端を0番目として数えます。</Marker>10進数の「一の位・十の位・百の位」を右から数えるのと同じです。

| 桁の位置 | 2番目 | 1番目 | 0番目 |
|---|---|---|---|
| その桁の重み | 2^2 = 4 | 2^1 = 2 | 2^0 = 1 |
| 5 = `101` の場合 | 1 | 0 | 1 |

桁の番号が「2の何乗か」の指数と一致するので、i番目の桁を `1 << i`（2^i）で狙い撃ちできます。5 = 4 + 1 なので、2番目と0番目が1です。

### コードで書く

```typescript
function canMakeSum(nums: number[], x: number): boolean {
  const n = nums.length;
  for (let bit = 0; bit < (1 << n); bit++) {   // 1 << n は 2^n
    let sum = 0;
    for (let i = 0; i < n; i++) {
      if (bit & (1 << i)) sum += nums[i];      // bitのi桁目が立っていたらi番目を選ぶ
    }
    if (sum === x) return true;
  }
  return false;
}
```

使うビット演算は次の3つです。

| 演算 | 意味 |
|---|---|
| `1 << n` | 2^n。ループの上限（選び方の総数）に使う |
| `1 << i` | i番目の桁だけが1の数を作る |
| `bit & (1 << i)` | bitのi番目の桁が1か調べる。1なら2^i、0なら0になる |

`&`（ビットAND）は、**両方とも1の桁だけを1として残す**演算です。

### `bit & (1 << i)` を手で計算してみる

bit = 5（`101`）、つまり「0番目と2番目を選ぶ」選び方で、内側のループがどう動くかを追います。

| i | `1 << i` | `5 & (1 << i)` | 結果 | 判定 |
|---|---|---|---|---|
| 0 | `001` | `101 & 001` | `001`（1） | 0以外 → 0番目の3を足す |
| 1 | `010` | `101 & 010` | `000`（0） | 0 → 1番目の5は足さない |
| 2 | `100` | `101 & 100` | `100`（4） | 0以外 → 2番目の7を足す |

合計は3 + 7 = 10で、最初の表の5の行と一致します。`1 << i` が「i番目の桁だけ1」の物差しになっていて、`&` を取ると、bitのその桁が1のときだけ物差しの1が残ります。JavaScriptの `if` は0を偽、それ以外を真として扱うので、`if (bit & (1 << i))` だけで判定できます。

外側が2^N回、その1回ごとに内側がN回まわるので、計算量はO(2^N × N)です。N = 20なら2^20 × 20 ≈ 2,100万回。1秒あたり10^8回という目安の5分の1ほどなので、十分間に合います。

<Marker>「部分集合」「選ぶ/選ばない」「N ≤ 20前後」の三点セットが揃ったらbit全探索</Marker>——これは最も再現性の高いパターン認識の1つです。

### よくある間違い

<SpeechBubble character="/images/question_woman_04_color.png" name="学習者">
「i番目の桁が1か」を調べたいんだから、`if (bit & (1 << i) === 1)` って書けばいいんだよね？
</SpeechBubble>

これは2つの理由で動きません。

<Callout type="warning" title="=== 1 と比べてはいけない">
1つ目は演算子の優先順位です。JavaScriptでは `===` が `&` より先に計算されるので、`bit & ((1 << i) === 1)` と解釈されます。i ≥ 1 では `(1 << i) === 1` が `false`（数値の0扱い）になり、`bit & 0` で**常に0**です。0番目以外の要素が一度も選ばれません。

2つ目は結果の値です。括弧を付けて `(bit & (1 << i)) === 1` としても、`&` の結果は0か2^iなので、1と一致するのはi = 0のときだけです。

「1か」ではなく「**0でないか**」で判定します。`if (bit & (1 << i))` か、明示したいなら `if ((bit & (1 << i)) !== 0)` と書きます。
</Callout>

0か1で受け取りたいときは、bitを右にi桁ずらしてから右端を取る `(bit >> i) & 1` という書き方もあります。こちらは結果が必ず0か1になるので、`=== 1` と比べても正しく動きます。

<Callout type="note" title="Nが31以上だとビット演算は使えない">
JavaScriptのビット演算は、数値を32ビット整数に変換してから計算します。そのため `1 << 31` は `-2147483648`（負の数）になり、`1 << 32` は `1` に戻ってしまいます。bit全探索が使えるのはN ≤ 20前後なので、試験で困ることはまずありませんが、「ビット演算は32ビットまで」と覚えておきましょう。
</Callout>

## 全探索から他の解法への橋

冒頭で「応用解法は全探索の無駄削り」と言いました。この見取り図を持っておくと、Part 3の残りがつながって見えます。

| 全探索の課題 | 削り方 | 章 |
|---|---|---|
| 選択肢を全部試すのが無駄（実は一番良い選択が自明） | **貪欲法**: 毎回ベストだけ選ぶ | [第9章](/books/coding-test/09-greedy) |
| 同じ計算を何度も繰り返している | **DP**: 計算結果を表に記録して再利用 | [第10章](/books/coding-test/10-dynamic-programming) |
| 答えの候補が単調に並んでいる | **二分探索**: 半分ずつ捨てる | [第8章](/books/coding-test/08-sort-and-binary-search) |

面接でも「まず全探索ならO(2^N)です。ただ同じ部分問題を何度も解いているので、DPでO(NX)に落とせます」という**全探索起点の説明**は、思考の筋道が伝わる強い型です。

## この章のパターンの見分け方

| 問題文のシグナル | 使う型 |
|---|---|
| 「組み合わせを選ぶ」+ Nが数百 | 多重ループ（j = i + 1 開始） |
| 「並べ方」「訪れる順序」+ N ≤ 10 | 順列全列挙 |
| 「選ぶ/選ばない」「部分集合」+ N ≤ 20前後 | **bit全探索** |
| 制約が小さい（何でも間に合う） | 迷わず全探索 |

## まとめ

- 全探索は「力任せ」ではなく、**制約が許すなら最優先で選ぶべき解法**。バグりにくさは正義
- 組み合わせの多重ループは `j = i + 1` 開始で重複を防ぐ
- **bit全探索**: 整数0〜2^N-1を「選び方」とみなす。桁は右端が0番目。`bit & (1 << i)` は「0でないか」で判定する（`=== 1` と比べない）
- 「選ぶ/選ばない × N ≤ 20」はbit全探索の三点セット
- 貪欲法・DP・二分探索は全探索の無駄を削った姿。まず全探索で考えてから削る

次章は「候補を半分ずつ捨てる」削り方——ソートと二分探索です。「答えで二分探索する」という発想の転換まで進みます。
