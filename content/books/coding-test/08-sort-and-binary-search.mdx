この章では、ソート済みの配列から値を探す**二分探索**と、その前提になるソートの使い方を扱います。

先頭から1つずつ調べる線形探索は、要素数Nに対してO(N)かかります（[第2章](/books/coding-test/02-big-o)）。二分探索は、ソート済みの配列の真ん中を1回調べるたびに候補を半分に減らすので、O(log N)で終わります。候補が10^9個あっても、半分にする操作を30回繰り返せば1個まで減ります（2^30 ≈ 1.07 × 10^9）。

## ソートしておくと何が楽になるか

ソートの計算量はO(N log N)です。N = 10^5 なら約170万回なので、制約上はまず問題になりません。ソートしたあとの配列には「小さい順に並んでいる」という性質があり、これを使うと後の処理を短く速く書けます。

例として、配列に同じ値が2回以上含まれるかを調べます。ソートしなければ、すべての組を比べる二重ループになります。

```typescript
// ソートしない場合。全ペアを比べるので O(N²)
function hasDuplicateNaive(a: number[]): boolean {
  for (let i = 0; i < a.length; i++) {
    for (let j = i + 1; j < a.length; j++) {
      if (a[i] === a[j]) return true;
    }
  }
  return false;
}

// ソートする場合。同じ値は隣に並ぶので、隣同士だけ比べればよい。O(N log N)
function hasDuplicate(a: number[]): boolean {
  const s = [...a].sort((x, y) => x - y);
  for (let i = 1; i < s.length; i++) {
    if (s[i] === s[i - 1]) return true;
  }
  return false;
}
```

N = 10^5 のとき、二重ループは約5 × 10^9回の比較になり時間切れです。ソート版はソートの約170万回と、隣同士の比較10^5回で済みます。

重複の判定だけならSet（[第4章](/books/coding-test/04-hashmap-and-set)）でも解けますが、「ソートすれば近い値が隣に来る」という性質は重複以外にも使えます。たとえば「差がいちばん小さい2つの数」は、ソートしてから隣同士の差を調べるだけで求まります。差が最小になる2数は、ソート後に必ず隣り合っているからです。

ソート済みであることを使う手法は、この章の二分探索のほかに、両端から2つの添字を動かす二つのポインタ（[第3章](/books/coding-test/03-arrays-and-strings)）や、終了時刻の早い順などに並べてから選んでいく貪欲法（[第9章](/books/coding-test/09-greedy)）があります。

### ソートは組み込みの sort を使う

上でソートをO(N log N)と書いたのは、言語に組み込まれた `sort` を使った場合の話です。自分で素朴なソートを書くと、そうはなりません。

代表例が**バブルソート**です。隣り合う2つを比べて、順番が逆なら入れ替える。これを端から端まで繰り返すと、大きい数字から順に右端へ押し出されていきます。

1周でN回近く比べ、それをN周近く繰り返すので、計算量は **O(N²)** です。N = 10^5 なら比較は約10^10回で、10^8回ルール（[第2章](/books/coding-test/02-big-o)）の100倍になり、時間切れになります。

JavaScriptの `Array.prototype.sort` は、V8（ChromeやNode.jsのエンジン）ではTimSortというO(N log N)のアルゴリズムで実装されています（[V8公式ブログ](https://v8.dev/blog/array-sort)）。

本番で書くことは、まずありません。ただ「二重ループで隣同士を入れ替えている」コードを見たらO(N²)だと気づけるようにしておくと、自分のコードが遅い理由を探すときに役立ちます。ソートは `arr.sort((a, b) => a - b)` の1行で書いてください。比較関数を省くと数値が文字列として比べられ、`[10, 9, 1]` が `[1, 10, 9]` になります（[第3章](/books/coding-test/03-arrays-and-strings)）。

## 二分探索の基本形

> 昇順にソートされた配列 `sorted` に、値 `x` が含まれるかを判定してください。

```typescript
function binarySearch(sorted: number[], x: number): boolean {
  let left = 0;
  let right = sorted.length - 1;
  while (left <= right) {
    const mid = Math.floor((left + right) / 2);
    if (sorted[mid] === x) return true;
    if (sorted[mid] < x) left = mid + 1;   // mid とその左は x より小さいので候補から外す
    else right = mid - 1;                  // mid とその右は x より大きいので候補から外す
  }
  return false;
}
```

`left` と `right` は、「x があるとしたらこの範囲のどこか」という候補の両端です。真ん中の `mid` を見て、`sorted[mid]` が x より小さければ、配列は昇順なので mid より左もすべて x より小さく、まとめて候補から外せます。大きければ、mid より右をまとめて外します。

### 1ステップずつ追う

`sorted = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]`（添字は0〜9）で、`x = 23` を探します。

| 回 | left | right | mid | sorted[mid] | 判定 |
|---|---|---|---|---|---|
| 1 | 0 | 9 | 4 | 16 | 16 < 23 なので left = 5 |
| 2 | 5 | 9 | 7 | 56 | 56 > 23 なので right = 6 |
| 3 | 5 | 6 | 5 | 23 | 一致したので true |

配列にない `x = 20` の場合は次のようになります。

| 回 | left | right | mid | sorted[mid] | 判定 |
|---|---|---|---|---|---|
| 1 | 0 | 9 | 4 | 16 | 16 < 20 なので left = 5 |
| 2 | 5 | 9 | 7 | 56 | 56 > 20 なので right = 6 |
| 3 | 5 | 6 | 5 | 23 | 23 > 20 なので right = 4 |
| 4 | 5 | 4 | | | left > right なのでループを抜けて false |

10個の配列で、比較は最大でも4回です。

### `<=` と `mid ± 1` にしている理由

`while (left <= right)` の `=` を外すと、候補が1個だけ残った状態（left と right が同じ）でループを抜けてしまい、その1個を調べません。たとえば配列が `[23]` だけで `x = 23` のとき、left = 0、right = 0 なのでループに入らず、false を返します。

`left = mid + 1` を `left = mid` にすると、調べ終わった mid が候補に残り続けます。left = 5、right = 6 のとき mid は5なので、`sorted[5]` が x より小さいと left は5のまま変わらず、無限ループになります。

この書き方は「値があるかないか」を判定するだけなら十分です。ただ、「x以上が初めて現れる位置」や「xが何個あるか」のように境界の位置がほしくなると、`<=` か `<` か、`mid` か `mid - 1` か、最後に返すのは left か right か、を問題ごとに考え直すことになります。そこで次の書き方を使います。

## 境界を探す書き方（ng/ok型、めぐる式）

値そのものを探すのをやめて、「条件を満たすかどうか」が切り替わる位置を探します。競技プログラミングでは「めぐる式二分探索」という名前で知られている書き方です。

昇順の配列で、各要素について「x以上か」を並べると、前半は満たさず、後半は満たし、切り替わりは1回だけです。`a = [1, 3, 3, 3, 5, 8]`、`x = 3` の場合は次のとおりです。

| 添字 | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 値 | 1 | 3 | 3 | 3 | 5 | 8 |
| 3以上か | × | ○ | ○ | ○ | ○ | ○ |

最初の○の位置（ここでは1）を求めます。この位置を **lowerBound** と呼びます。変数は2つ使います。

- `ng` は「条件を満たさない」とわかっている位置
- `ok` は「条件を満たす」とわかっている位置

```typescript
// 「x以上が初めて現れる位置」（lowerBound）を求める
function lowerBound(sorted: number[], x: number): number {
  let ng = -1;                    // 配列の外。「x以上でない」側として扱う
  let ok = sorted.length;         // 配列の外。「x以上である」側として扱う
  while (ok - ng > 1) {
    const mid = Math.floor((ng + ok) / 2);
    if (sorted[mid] >= x) ok = mid;
    else ng = mid;
  }
  return ok;
}
```

### なぜ正しく求まるか

ループの間、次の2つがずっと成り立っています。

- `ng` は -1 か、`sorted[ng] < x` を満たす位置
- `ok` は配列の長さか、`sorted[ok] >= x` を満たす位置

mid が条件を満たせば `ok = mid`、満たさなければ `ng = mid` と更新するので、どちらの更新でもこの2つは崩れません。ループは `ok - ng` が1になったら終わります。そのとき ng と ok は隣同士で、ng 以下はすべて x 未満、ok 以上はすべて x 以上です。つまり ok が「x以上が初めて現れる位置」になります。

初期値の -1 と配列の長さは配列の外を指していますが、`ok - ng > 1` の間、mid は必ず ng と ok の間（両端を含まない）に来るので、`sorted[-1]` や `sorted[sorted.length]` を読むことはありません。

### 1ステップずつ追う

`a = [1, 3, 3, 3, 5, 8]` で `lowerBound(a, 3)` を実行します。

| 回 | ng | ok | mid | a[mid] | 判定 |
|---|---|---|---|---|---|
| 1 | -1 | 6 | 2 | 3 | 3 >= 3 なので ok = 2 |
| 2 | -1 | 2 | 0 | 1 | 1 < 3 なので ng = 0 |
| 3 | 0 | 2 | 1 | 3 | 3 >= 3 なので ok = 1 |
| 4 | 0 | 1 | | | ok - ng = 1 なので終了。1を返す |

端のケースも、追加の分岐なしで正しい値が返ります。

- `x = 10`（全要素より大きい）なら、一度も ok が更新されず、6（配列の長さ）が返る。「x以上の要素はない」という意味になる
- `x = 0`（全要素より小さい）なら、一度も ng が更新されず、0 が返る
- 空配列なら ng = -1、ok = 0 でループに入らず、0 が返る

### 条件を変えると別の境界が求まる

条件式を `sorted[mid] > x` に変えると、「xより大きい値が初めて現れる位置」になります。これを **upperBound** と呼びます。上の配列で `upperBound(a, 3)` は4です。

```typescript
function upperBound(sorted: number[], x: number): number {
  let ng = -1;
  let ok = sorted.length;
  while (ok - ng > 1) {
    const mid = Math.floor((ng + ok) / 2);
    if (sorted[mid] > x) ok = mid;
    else ng = mid;
  }
  return ok;
}
```

ループの形は変わらず、変えたのは条件式1か所だけです。どの境界を探すときも、`<=` と `<` のどちらにするか、何を返すかを考え直す必要がありません。

### lowerBound で個数を数える

lowerBound と upperBound を組み合わせると、ソート済み配列の個数を数えられます。`a = [1, 3, 3, 3, 5, 8]` の場合です。

```typescript
lowerBound(a, 3)                       // 1  3未満の個数（位置と個数が同じ値になる）
a.length - lowerBound(a, 3)            // 5  3以上の個数
upperBound(a, 3) - lowerBound(a, 3)    // 3  ちょうど3の個数
lowerBound(a, 6) - lowerBound(a, 2)    // 4  2以上6未満の個数
```

要素が整数なら、`upperBound(a, x)` は `lowerBound(a, x + 1)` と同じ値になります。小数を含む配列では一致しないので、upperBound を使ってください。

この数え方が効くのは、同じ配列に何度も問い合わせる問題です。N, Q ≤ 10^5 で「x以上の要素は何個か」をQ回答える場合、毎回配列を数えるとO(NQ) = 10^10で時間切れになります。最初に1回ソートして、各問い合わせを lowerBound で答えれば、O((N + Q) log N) で済みます。

JavaScriptには、C++の `std::lower_bound` やPythonの `bisect_left` にあたる関数がありません。`indexOf` や `findIndex` は先頭から順に調べるO(N)です。lowerBound は自分で書くことになるので、[付録のスニペット集](/books/coding-test/15-appendix-snippets)に載せています。

## 答えを二分探索する

二分探索で調べる対象は、配列の添字に限りません。「答えの値を1つ決めれば、それが実現できるか判定できる」問題では、答えの値の範囲を二分探索できます。

> N本の丸太があり、i本目の長さは `logs[i]` です。丸太を切って、同じ長さLの棒をK本以上作りたい。Lは整数とします。作れるLの最大値を求めてください。余った部分は捨ててかまいません。（N, K ≤ 10^5、丸太の長さは10^9以下）

Lを直接計算する式はありません。しかしLを1つ決めれば、K本作れるかはすぐ判定できます。長さ `logs[i]` の丸太からは `Math.floor(logs[i] / L)` 本取れるので、全部の丸太について足して、K以上かを見ればよいだけです。判定はO(N)です。

`logs = [7, 10, 13]`、`K = 5` で、Lごとに判定した結果を並べます。

| L | 7から | 10から | 13から | 合計 | 5本作れるか |
|---|---|---|---|---|---|
| 3 | 2 | 3 | 4 | 9 | ○ |
| 4 | 1 | 2 | 3 | 6 | ○ |
| 5 | 1 | 2 | 2 | 5 | ○ |
| 6 | 1 | 1 | 2 | 4 | × |
| 7 | 1 | 1 | 1 | 3 | × |

答えは5です。Lを大きくすると、どの丸太から取れる本数も増えることはないので、合計も増えません。そのため「作れる」はLが小さい側にまとまり、どこか1か所で「作れない」に切り替わります。この性質を**単調性**と呼びます。

lowerBoundで見た「×××○○○」と並びが逆なだけで、境界が1か所という形は同じです。前の節のng/ok型がそのまま使えます。Lを1から順に試すと最大10^9回の判定が必要ですが、二分探索なら約30回で済みます。

```typescript
function maxLength(logs: number[], k: number): number {
  const canCut = (len: number): boolean => {
    let total = 0;
    for (const log of logs) total += Math.floor(log / len);
    return total >= k;
  };

  let ok = 0;                     // 長さ0は「作れる」側として扱う
  let ng = 1e9 + 1;               // 最長の丸太より長い棒は1本も作れない
  while (ng - ok > 1) {
    const mid = Math.floor((ok + ng) / 2);
    if (canCut(mid)) ok = mid;
    else ng = mid;
  }
  return ok;
}
```

初期値は次のように決めています。

- `ok = 0` は「作れる」側に置いた値。`canCut(0)` を呼ぶと0で割ることになるが、mid は常に ok より大きいので呼ばれない
- `ng = 1e9 + 1` は、丸太の長さの上限10^9より長い値。この長さでは1本も取れないので、Kが1以上なら必ず「作れない」側になる
- ループを抜けて ok が0のままなら、長さ1でもK本作れないという意味になる

計算量はO(N log 10^9)で、約10^5 × 30 = 3 × 10^6回です。合計 `total` は最大で10^5 × 10^9 = 10^14 ですが、JavaScriptのnumberが誤差なく扱える整数の上限（`Number.MAX_SAFE_INTEGER`、約9 × 10^15）より小さいので問題ありません。

### 最大値を最小にする問題

丸太の例は「作れる最大の値」を求める問題でした。逆向きの「最大値を最小にする」問題も同じ形で解けます。

> N個の荷物を、並び順を変えずに前から順にK台のトラックへ分けて積みます。1台に積む重さの合計を「積載量」とするとき、各トラックの積載量の最大値を最小にしてください。（荷物の重さは1以上）

判定は「積載量の上限をCとしたとき、K台以内で積めるか」です。前から順に積んでいき、Cを超えそうになったら次のトラックに移ります。Cを大きくすると必要な台数は増えないので、ここにも単調性があります。今度はCが大きい側が「積める」なので、ng を小さい側、ok を大きい側に置きます。

```typescript
function minCapacity(weights: number[], k: number): number {
  const canLoad = (cap: number): boolean => {
    let trucks = 1;
    let load = 0;
    for (const w of weights) {
      if (w > cap) return false;            // 1個だけで上限を超える荷物がある
      if (load + w > cap) {                 // 今のトラックに載らないので次のトラックへ
        trucks++;
        load = 0;
      }
      load += w;
    }
    return trucks <= k;
  };

  let ng = 0;                                     // 積載量0では積めない
  let ok = weights.reduce((s, w) => s + w, 0);    // 全部を1台に積める量なら必ず積める
  while (ok - ng > 1) {
    const mid = Math.floor((ng + ok) / 2);
    if (canLoad(mid)) ok = mid;
    else ng = mid;
  }
  return ok;
}
```

答えで二分探索が使えるかどうかは、次の3点で判断します。

1. 問題文に「最大値を最小に」「最小値を最大に」「〜できる最大の」などがある
2. 答えの値を1つ決めれば、実現できるかをO(N)程度で判定できる
3. 値を大きく（または小さく）していくと、判定結果が1回だけ切り替わる

3が成り立たないと、二分探索は間違った答えを返します。判定関数を書いたら、値を動かしたときに結果が行ったり来たりしないかを確かめてください。

## 座標圧縮

ソートを前処理に使う例をもう1つ紹介します。**座標圧縮**は、値の大小関係だけを残して、値を 0, 1, 2, … に付け替える処理です。

```typescript
const values = [100, 5, 1000000000, 5, 42];

const sorted = [...new Set(values)].sort((a, b) => a - b);   // [5, 42, 100, 1000000000]
const rank = new Map(sorted.map((v, i) => [v, i]));          // 5→0, 42→1, 100→2, 1000000000→3
const compressed = values.map((v) => rank.get(v)!);          // [2, 0, 3, 0, 1]
```

値を配列の添字に使いたいときに必要になります。たとえば各値の出現回数を配列で数えたいとき、値が10^9まであると長さ10^9の配列は作れません。値の種類はN個以下なので、圧縮すれば長さNの配列で済みます。

`rank.get(v)` の代わりに `lowerBound(sorted, v)` でも同じ番号が得られます。Mapなら1回O(1)、lowerBoundなら1回O(log N)です。

## 問題文から見分ける

| 問題文の特徴 | 使う方法 |
|---|---|
| ソート済み（またはソートしてよい）配列で、値を探す・個数を数える | lowerBound / upperBound |
| 同じ配列に「x以上は何個か」などの問い合わせが何度も来る | ソート1回 + lowerBound |
| 「最大値の最小化」「最小値の最大化」「〜できる最大のL」 | 答えで二分探索 |
| 値の範囲が10^9まであるが、値を添字に使いたい | 座標圧縮 |

## まとめ

- ソートの計算量はO(N log N)。ソートすると近い値が隣に並び、重複の判定や差の最小値が隣同士の比較で求まる。ソートは組み込みの `sort` に比較関数を渡して使う
- 二分探索は、ソート済みの配列の真ん中を見て候補を半分ずつ減らす。計算量はO(log N)
- 境界の位置を求めるときは、ng/ok の2変数を配列の外（-1 と配列の長さ）から始め、`ok - ng > 1` の間 mid で狭めていく。条件式を変えるだけで lowerBound と upperBound を書き分けられる
- `upperBound(a, x) - lowerBound(a, x)` で、ちょうどxの個数が求まる
- 答えの値を決めれば判定でき、その判定に単調性があるなら、答えの範囲を二分探索できる。計算量は（判定の計算量）× log（答えの範囲）
- 座標圧縮は、重複を除いてソートし、Mapで値から順位を引けるようにする処理

次の第9章は貪欲法です。ソートしたあと、毎回その時点で最もよいものを選んでいく解き方で、どんな問題なら正しい答えが出るのかを扱います。
