この章では、グラフ問題で使う2つのアルゴリズムを学びます。

- **ダイクストラ法** — 道路ごとに距離や料金が違うとき、合計コストが最小の経路を求める
- **Union-Find** — 道路を追加しながら、2地点がつながっているかを判定する

どちらもグラフを扱いますが、解く問題は別です。前の章を読んでいなくても進められるように、必要な言葉から確認します。[木とグラフの基礎](/books/coding-test/06-trees-and-graphs)を読んでいる場合は、復習として流し読みしてください。

## 最初に知っておく言葉

グラフとは、都市や人などの**点**と、点どうしのつながりを表す**線**の集まりです。

| 言葉 | この章での意味 | 道路にたとえると |
| --- | --- | --- |
| **頂点**（ノード） | グラフを構成する点 | 都市、駅、交差点 |
| **辺**（エッジ） | 2つの頂点を結ぶ線 | 道路、路線 |
| **重み** | 辺を1本通るときのコスト | 距離、所要時間、運賃 |
| **経路** | 複数の辺を順番にたどった道筋 | 東京→名古屋→大阪のような移動順 |
| **最短距離** | 経路上の重みを足した最小値 | 合計時間や合計運賃の最小値 |
| **連結** | 辺を何本かたどって行き来できる状態 | 途中の都市を経由して到達できる状態 |

<Callout type="note" title="「最短」は距離だけではない">
  問題文の「重み」が時間なら最短時間、料金なら最安料金を求めます。ダイクストラ法が最小にするのは、辺に書かれた数値の合計です。
</Callout>

2つのアルゴリズムの役割を先に分けておきましょう。

| 知りたいこと | 使うアルゴリズム |
| --- | --- |
| AからBまでの合計コストはいくつか | ダイクストラ法 |
| AからBまで、どの頂点を通ればよいか | ダイクストラ法 + 経路復元 |
| AとBは同じグループに属するか | Union-Find |
| AとBを同じグループにまとめたい | Union-Find |

## ダイクストラ法が解く問題

次の有向グラフを考えます。矢印が進める向き、矢印の横の数字が移動コストです。

<MermaidDiagram
  chart={`
flowchart LR
    A["0"] -->|4| B["1"]
    A -->|1| C["2"]
    C -->|2| B
    B -->|1| D["3"]
    C -->|5| D
`}
/>

頂点0から頂点3へ進む経路には、次の候補があります。

- `0 → 1 → 3` の合計は `4 + 1 = 5`
- `0 → 2 → 3` の合計は `1 + 5 = 6`
- `0 → 2 → 1 → 3` の合計は `1 + 2 + 1 = 4`

通る辺が多い3つ目の経路が最短です。<Marker>重み付きグラフでは、辺の本数が少ない経路が最短とは限りません。</Marker>

幅優先探索（BFS）は「通る辺の本数」が少ない順に調べます。そのため、すべての辺の重みが同じ場合には最短距離を求められます。辺ごとに重みが違う場合は、**現在わかっている合計コストが小さい頂点から調べる**ダイクストラ法を使います。

## ダイクストラ法を手で追う

ダイクストラ法では、スタートから各頂点までの「現時点でわかっている最小コスト」を `dist` 配列に記録します。まだ経路を見つけていない頂点には `Infinity` を入れます。JavaScriptの `Infinity` は、どの有限の数値よりも大きい値です。

最初は頂点0にいるので、`dist` は次の状態です。

```text
頂点:  0  1  2  3
dist:  0  ∞  ∞  ∞
```

その後は、`dist` が最小の未処理頂点を選び、その頂点から1本で進める隣の頂点を更新します。

| 手順 | 選ぶ頂点 | 更新内容 | `dist` |
| --- | --- | --- | --- |
| 開始 | 0 | スタートだけ0にする | `[0, ∞, ∞, ∞]` |
| 1 | 0 | 1へコスト4、2へコスト1で行ける | `[0, 4, 1, ∞]` |
| 2 | 2 | 2経由なら1へコスト3、3へコスト6 | `[0, 3, 1, 6]` |
| 3 | 1 | 1経由なら3へコスト4 | `[0, 3, 1, 4]` |
| 4 | 3 | 更新できる頂点がない | `[0, 3, 1, 4]` |

頂点1へ直接進むコストは4でした。しかし、`0 → 2 → 1` なら合計3です。このように、すでに見つけた値より小さい値を発見したら `dist` を上書きします。この更新を**緩和**と呼ぶ資料もあります。

<SpeechBubble character="/images/usingcomputer_suit_woman_color.png" name="学習者">
  どうして、いちばん小さい `dist` の頂点から選べばよいの？ あとで近道が見つかるかもしれないよね。
</SpeechBubble>

まだ選んでいない頂点の `dist` は、いま選んだ値以上です。さらに、この章では重みが0以上の辺だけを扱うため、その先へ進んでも合計コストは小さくなりません。したがって、最小の頂点までの距離は、それより小さくなる経路がもう現れないと判断できます。

この判断が成り立つため、<Marker>ダイクストラ法は負の重みを含むグラフには使えません。</Marker>重み0の辺は使用できます。

## 優先度付きキューで最小値を取り出す

毎回 `dist` 全体を見て最小の頂点を探すと、頂点が増えたときに時間がかかります。そこで、**優先度付きキュー**というデータ構造を使います。

普通のキューは先に入れた値から取り出します。優先度付きキューは、入れた順番に関係なく、優先度が最も高い値を取り出します。ダイクストラ法では「距離が小さいほど優先度が高い」と決めます。

```text
追加: [距離4, 頂点1]
追加: [距離1, 頂点2]
取り出す値: [距離1, 頂点2]
```

優先度付きキューは**ヒープ**という仕組みで実装するのが一般的です。TypeScriptの標準機能には優先度付きキューがないため、本書では最小値を取り出す `MinHeap` クラスを使います。クラス本体は[付録のMinHeap](/books/coding-test/15-appendix-snippets)に掲載しています。

この章で使う操作は3つだけです。

| 操作 | 役割 |
| --- | --- |
| `heap.push(value)` | 候補を追加する |
| `heap.pop()` | 距離が最小の候補を取り出す |
| `heap.size` | 候補が残っている個数を取得する |

## 重み付きグラフを隣接リストにする

コードでは、各頂点から「どこへ、いくつのコストで進めるか」を配列に保存します。この形式を**隣接リスト**と呼びます。

```typescript
type Edge = [to: number, cost: number];

const N = 4;
const edges: [from: number, to: number, cost: number][] = [
  [0, 1, 4],
  [0, 2, 1],
  [2, 1, 2],
  [1, 3, 1],
  [2, 3, 5],
];

const graph: Edge[][] = Array.from({ length: N }, () => []);
for (const [from, to, cost] of edges) {
  graph[from].push([to, cost]);
}
```

たとえば `graph[0]` には `[[1, 4], [2, 1]]` が入ります。これは「頂点0から頂点1へコスト4、頂点2へコスト1で進める」という意味です。

道路のように両方向へ進める**無向グラフ**なら、逆向きの辺も追加します。

```typescript
graph[from].push([to, cost]);
graph[to].push([from, cost]);
```

## ダイクストラ法をTypeScriptで実装する

**構文：** `dijkstra(N, graph, start)`

| 引数 | 渡すもの | 説明 |
| --- | --- | --- |
| `N` | `number` | 頂点の個数。頂点番号は0から`N - 1`まで |
| `graph` | `[number, number][][]` | `graph[v]`に、頂点`v`から進める`[行き先, 重み]`を入れた隣接リスト |
| `start` | `number` | 最短距離を測り始める頂点番号 |

**戻り値：** `start`から各頂点までの最短距離を入れた`number[]`。到達できない頂点は`Infinity`

```typescript
function dijkstra(
  N: number,
  graph: [number, number][][],
  start: number,
): number[] {
  const dist = new Array(N).fill(Infinity);
  dist[start] = 0;

  // 要素は [スタートからの距離, 頂点番号]
  const heap = new MinHeap<[number, number]>((a, b) => a[0] - b[0]);
  heap.push([0, start]);

  while (heap.size > 0) {
    const [d, v] = heap.pop()!;

    // より短い距離がすでに見つかっている候補は使わない
    if (d > dist[v]) continue;

    for (const [next, cost] of graph[v]) {
      const newDistance = dist[v] + cost;
      if (newDistance < dist[next]) {
        dist[next] = newDistance;
        heap.push([newDistance, next]);
      }
    }
  }

  return dist;
}
```

処理の流れは、手で追った4段階と同じです。

1. スタートの距離を0、ほかを`Infinity`にする
2. ヒープから距離が最小の候補を取り出す
3. その頂点から進める辺を調べ、より短い経路なら`dist`を更新する
4. ヒープが空になるまで2〜3を繰り返す

### 古い候補をスキップする理由

先ほどの例では、頂点1の候補として最初に `[4, 1]` がヒープへ入ります。その後、頂点2を経由する短い経路が見つかり、`[3, 1]` も入ります。

`[3, 1]` を先に処理した時点で `dist[1]` は3です。あとから取り出した `[4, 1]` は古い情報なので、次の1行で捨てます。

```typescript
if (d > dist[v]) continue;
```

古い候補を削除する機能を `MinHeap` に持たせず、取り出した時点で無視する設計です。この1行を忘れても答えが合う場合はありますが、同じ頂点を何度も調べて遅くなるため必ず入れます。

### ダイクストラ法の計算量

**計算量**とは、入力が増えたときに処理回数がどの程度増えるかを表す目安です。頂点数を`N`、辺数を`M`とすると、ダイクストラ法の計算量は`O((N + M) log N)`です。`log N`の部分はヒープへの追加と取り出しにかかる時間を表します。`N`と`M`が`100,000`程度でも使えることが多い計算量です。

## 最短経路そのものを復元する

`dist`でわかるのは最短距離です。通った頂点も必要なら、距離を更新したときに「どの頂点から来たか」を `prev` 配列へ保存します。

```typescript
const prev = new Array<number>(N).fill(-1);

// dist[next]を更新するif文の中に追加する
prev[next] = v;
```

ゴールから `prev` を逆向きにたどり、最後に配列を反転します。

```typescript
function restorePath(prev: number[], goal: number): number[] {
  const path: number[] = [];
  for (let v = goal; v !== -1; v = prev[v]) {
    path.push(v);
  }
  return path.reverse();
}
```

例のグラフで頂点3を指定すると、`[0, 2, 1, 3]`を返します。到達できないゴールでは、復元前に `dist[goal] === Infinity` を確認してください。

## Union-Findが解く問題

次は最短距離ではなく、**2つの頂点が同じグループに属するか**を扱います。

> 5個の島がある。橋を順番に追加しながら、「島aから島bへ行けるか」という質問に答えよ。

橋を追加するたびに島のグループが合体します。

| 操作 | グループの状態 | 質問への答え |
| --- | --- | --- |
| 最初 | `{0} {1} {2} {3} {4}` | すべて別 |
| 0と1を結ぶ | `{0, 1} {2} {3} {4}` | 0と2はつながっていない |
| 3と4を結ぶ | `{0, 1} {2} {3, 4}` | 3と4はつながっている |
| 1と2を結ぶ | `{0, 1, 2} {3, 4}` | 0と2はつながっている |

橋がすべて追加されたあとなら、深さ優先探索（DFS）や幅優先探索（BFS）でグループを調べられます。しかし、橋の追加と質問が交互に来る問題で、質問のたびにグラフ全体を探索し直すのは無駄です。

**Union-Find**は、グループの合体と同一グループ判定だけに機能を絞り、どちらも高速に行うデータ構造です。**素集合データ構造**や**Disjoint Set Union**（DSU）とも呼ばれます。

<Figure src="/images/meeting_color.png" alt="複数のグループが合流するイメージ" caption="橋をかける、友達関係を結ぶ、チームを統合する問題ではUnion-Findを疑う" maxWidth="180px" />

## 代表者を使ってグループを表す

Union-Findは、各グループを木の形で管理します。ここでいう**木**とは、各頂点から親をたどると、親を持たない頂点へ着く階層構造です。一番上にある頂点を**根**と呼び、Union-Findでは根をグループの**代表者**とします。同じ代表者へたどり着く頂点は、同じグループです。

```text
parent[0] = 0  ← 頂点0が代表者
parent[1] = 0  ← 頂点1の親は0
parent[2] = 1  ← 2 → 1 → 0とたどるので、頂点2の代表者も0
```

この状態では、0・1・2が同じグループです。代表者はグループを識別するための内部的な番号であり、特別な意味を持つ頂点ではありません。

Union-Findは次の操作を提供します。

| 操作 | 引数 | 戻り値 | 役割 |
| --- | --- | --- | --- |
| `find(x)` | 頂点`x` | 代表者の番号 | 親をたどって`x`の代表者を探す |
| `union(a, b)` | 頂点`a`、`b` | なし | 2つのグループを合体する |
| `same(a, b)` | 頂点`a`、`b` | `boolean`（`true`または`false`） | 代表者が同じかを判定する |

### 経路圧縮で木を浅くする

親を何段もたどる木は、`find`に時間がかかります。そこで、`find`で代表者を見つけたついでに、途中の頂点を代表者へ直接つなぎ直します。この高速化を**経路圧縮**と呼びます。

<MermaidDiagram
  chart={`
flowchart LR
    A["圧縮前: 3"] --> B["2"]
    B --> C["1"]
    C --> D["0（代表）"]
    E["圧縮後: 3"] --> H["0（代表）"]
    F["2"] --> H
    G["1"] --> H
`}
/>

もう1つの高速化が**ランクによる合併**です。`rank`は木の高さの目安であり、グループの人数ではありません。背の低い木を背の高い木の下へ付けると、合体後の木が深くなりにくくなります。

## Union-FindをTypeScriptで実装する

**構文：** `new UnionFind(n)`

| 引数 | 渡すもの | 説明 |
| --- | --- | --- |
| `n` | `number` | 要素数。要素番号は0から`n - 1`まで |

**戻り値：** 最初は各要素が別々のグループに属する`UnionFind`オブジェクト（クラスから作成した値を**インスタンス**と呼ぶ）

```typescript
class UnionFind {
  private parent: number[];
  private rank: number[];

  constructor(n: number) {
    // 最初は全員が自分自身を代表者とする
    this.parent = Array.from({ length: n }, (_, i) => i);
    this.rank = new Array(n).fill(0);
  }

  find(x: number): number {
    if (this.parent[x] !== x) {
      // 代表者を探し、次回から直接たどれるようにつなぎ直す
      this.parent[x] = this.find(this.parent[x]);
    }
    return this.parent[x];
  }

  union(a: number, b: number): void {
    const rootA = this.find(a);
    const rootB = this.find(b);

    // すでに同じグループなら何もしない
    if (rootA === rootB) return;

    // ランクが小さい木を大きい木の下へ付ける
    if (this.rank[rootA] < this.rank[rootB]) {
      this.parent[rootA] = rootB;
    } else if (this.rank[rootA] > this.rank[rootB]) {
      this.parent[rootB] = rootA;
    } else {
      this.parent[rootB] = rootA;
      this.rank[rootA]++;
    }
  }

  same(a: number, b: number): boolean {
    return this.find(a) === this.find(b);
  }
}
```

島の例は、次のように処理できます。

```typescript
const uf = new UnionFind(5);

uf.union(0, 1);
console.log(uf.same(0, 2)); // false

uf.union(3, 4);
console.log(uf.same(3, 4)); // true

uf.union(1, 2);
console.log(uf.same(0, 2)); // true
```

`union(1, 2)`は、頂点1だけを頂点2へつなぐ操作ではありません。1が属するグループ`{0, 1}`と、2が属するグループ`{2}`を丸ごと合体します。

<SpeechBubble character="/images/oksign_man_color.png" name="メンター">
  Union-Findで大切なのは、`union`の前に両方の代表者を`find`することです。頂点そのものではなく、グループの根どうしをつなぎます。
</SpeechBubble>

### Union-Findの計算量とできないこと

経路圧縮とランクによる合併を組み合わせると、1回の操作は実用上ほぼ`O(1)`、つまり要素数が増えても処理時間がほとんど増えません。厳密には複数回の操作を平均して`O(α(N))`と表します。`α(N)`は非常にゆっくり増える関数で、現実的な入力サイズでは5未満です。

一方、Union-Findが得意なのはグループの合体です。辺の削除や、1つのグループを2つへ分割する操作は扱えません。また、`same(a, b)`でつながっていることは判定できますが、実際にどの頂点を通るかは取得できません。

## BFS・ダイクストラ法・Union-Findの選び方

| 問題文で求められているもの | 辺の状態 | 選ぶ道具 |
| --- | --- | --- |
| 最小手数、通る辺の最小本数 | すべて同じ重み | BFS |
| 最小距離、最小時間、最安料金 | 0以上で辺ごとに違う重み | ダイクストラ法 |
| 2頂点が行き来できるか | 辺が固定されている | DFSまたはBFS |
| 2頂点が同じグループか | 辺を追加しながら質問される | Union-Find |

<Callout type="warning" title="名前ではなく、求める答えで選ぶ">
  「道路」や「友達」という単語だけではアルゴリズムを決められません。合計コストが必要ならダイクストラ法、つながっているかだけならDFS・BFS・Union-Findを問題の操作に応じて選びます。
</Callout>

## よくあるハマりどころ

### ダイクストラ法の注意点

- 無向グラフなのに片方向の辺しか隣接リストへ追加していない
- `dist[start] = 0`や、最初の`heap.push([0, start])`を忘れている
- ヒープから取り出した古い候補を`if (d > dist[v]) continue`で捨てていない
- 負の重みがあるのにダイクストラ法を使っている
- 最短経路が必要なのに`prev`を記録していない

### Union-Findの注意点

- `parent[a] = b`のように頂点どうしを直接つなぎ、代表者どうしを合体していない
- `find`が内側で呼び出した`find`の結果を`parent[x]`へ代入せず、経路圧縮が働いていない
- グループの人数が必要なのに、木の高さの目安である`rank`を人数として使っている
- 辺を削除する問題へUnion-Findを使おうとしている

## まとめ

- **ダイクストラ法**は、重みが0以上のグラフで、スタートから各頂点までの最小コストを求める
- `dist`は現時点の最小コストを表し、より短い経路を見つけるたびに更新する
- 優先度付きキューは、`dist`が小さい候補から高速に取り出すために使う
- **Union-Find**は、グループの合体と同一グループ判定を高速に行う
- `find`は代表者を探し、`union`は代表者どうしをつなぎ、`same`は代表者を比較する
- 最短コストが必要ならダイクストラ法、つながりだけが必要ならDFS・BFS・Union-Findから選ぶ

実装をすぐ使える形で手元に置きたい場合は、[付録のスニペット集](/books/coding-test/15-appendix-snippets)を利用してください。次章では、問題文のどの言葉からこれらの道具を選ぶかを練習します。
